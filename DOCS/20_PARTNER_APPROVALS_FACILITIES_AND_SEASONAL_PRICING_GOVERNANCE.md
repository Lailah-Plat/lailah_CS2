# 🏛️ وثيقة إدارة طلبات الشركاء والاعتمادات وتسعيرات الذروة والأسعار الموسمية
**Partner Onboarding Approvals, Venue/Service Asset Verification & Peak Pricing Governance**


## تحديث حاكم — محركات التسعير وفصل قواعدها (30-09-2026)

توجد ثلاث خدمات منفصلة، ولكل خدمة شاشة إدارة ومدخل إعداد ومحرك خادمي وسجل تغييرات مستقل:

| الخدمة | ما الذي تحدده | قاعدة التفعيل |
|---|---|---|
| **التسعير الموسمي والمناسبات المحددة** | أسعار موسم أو مناسبة مسماة مثل عيد الفطر، ضمن نطاق تاريخي معتمد. | تعمل فقط داخل فترة سريان المناسبة/الموسم المعتمدة. |
| **تسعير عطلة نهاية الأسبوع** | سعر الأيام الأسبوعية المعينة كعطلة في إعداد ليلة/المزود. | يعمل في أيام الأسبوع المحددة، ما لم تتغلب عليه قاعدة مناسبة أكثر تحديداً. |
| **تسعير الذروة الديناميكي** | تغيير متغير بناء على معيار ذروة تشغيلي تضبطه المنصة مثل الطلب أو التوفر. | يعمل وفق شروط محرك الذروة وحدوده، منفصلاً عن الموسم والويكند. |

لا تختزل هذه الخدمات في إعداد واحد ولا تدمج العطلة أو الموسم في الذروة الديناميكية.

تتضمن قاعدة السعر معرفاً وإصداراً ومالكاً ونطاقاً (قاعة/منتج/خدمة) ووقت بداية ونهاية ومنطقة زمنية وأساس الاحتساب والسعر/النسبة وسقفاً عند اعتماده وحالة موافقة. تغييرات الموسم تقدم قبل بدء السريان بمدة لا تقل عن 14 يوماً وفق النص الأصلي، وتتطلب موافقة الإدارة والسقف الذي تحدده الإدارة. تسري النسخة الجديدة على الحجوزات المستقبلية ضمن فترة السريان ولا تغير الحجوزات المؤكدة أو المدفوعة.

### أولوية التعارض وإعادة التحقق

إذا تعارضت قاعدة عطلة نهاية الأسبوع مع سعر مناسبة محددة بذاتها مثل عيد الفطر، تُطبق قاعدة المناسبة المحددة وحدها خلال فترة سريانها ولا تجمع معها قاعدة نهاية الأسبوع. لا يجمع النظام القواعد تلقائياً. الذروة الديناميكية محرك مستقل؛ وأي تعارض بينها وبين قاعدة أخرى يحتاج أولوية صريحة تضبطها المنصة، ولا يستنتج من قاعدة العيد/العطلة.

يعيد الخادم التحقق من التوفر وقواعد الأسعار الفعالة عند عرض السعر وقبل الدفع. إذا اختلف السعر عن عرض سابق، يُطلب قبول العميل قبل متابعة التحصيل. يحفظ الحجز لقطة مفصلة غير قابلة للتغيير من السعر النهائي والقواعد وإصداراتها ومصدرها والخصومات والضرائب المفصلة. واجهة React أو بيانات محلية لا تعد تطبيقاً خادمياً لهذه القواعد؛ المطلوب نماذج وواجهات API وتحقق خادمي ومعاملات ذرية واختبارات تغطي التداخلات والتغييرات.

تظل قيود الموافقة المسبقة والسقف وحماية الحجوزات الواردة في النص الأصلي سارية، وتفسر وفق هذه التفاصيل.

## 1. إدارة طلبات الشركاء والاعتمادات (Partner Requests & Asset Approvals Engine)

تضمن هذه الوحدة جودة المعروض بالمنصة من خلال إخضاع جميع المنشآت والقاعات والخدمات الجديدة لنظام تدقيق واعتمد إداري مبني على معايير الجودة الصارمة قبل العرض العام.

```
[إضافة قاعة / خدمة من لوحة المزود]
                │
                ▼
  (تحديد حالة الأصل: Pending Approval)
                │
                ▼
┌───────────────────────────────────────────────┐
│       مراجعة ومطابقة الإدارة (Admin)          │
│ • تدقيق الصور والتزام الحجم والقياسات        │
│ • تدقيق الفيديو والامتداد المعتمد             │
│ • مراجعة أسعار وشروط القاعة والخدمات          │
└───────────────────────┬───────────────────────┘
                        │
         ┌──────────────┴──────────────┐
         ▼                             ▼
   [اعتماد وتفعيل Approved]      [رفض الطلب مع السبب Rejected]
         │                             │
         ▼                             ▼
 (النشر المباشر بمتجر العملاء)   (إرسال الملاحظات للمزود للتعديل)
```

## 2. معايير وتدقيق وسائط القاعات والخدمات (Media Assets Verification Standard)

تُفحص الوسائط المرفوعة إلكترونياً للتأكد من الملاءمة البرمجية وتفادي استهلاك الباندويث أو إبطاء صفحات العملاء:

### 2.1 المواصفات الفنية المعتمدة للصور (Images Specifications)
- **الصيغ والامتدادات المسموحة:** `JPEG`, `JPG`, `PNG`, `WebP`.
- **الحد الأقصى لحجم الملف:** `500KB` للصورة الواحدة (رفض آلي لأي صورة تتجاوز هذا الحجم).
- **الأبعاد والقياسات الدنيا:** `960x540` بكسل.
- **الأبعاد والقياسات القصوى:** `1280x720` بكسل.
- **النسبة المفضلة:** `16:9` عريضة.

### 2.2 المواصفات الفنية المعتمدة لمقاطع الفيديو (Videos Specifications)
- **الصيغة المعتمدة:** `MP4` القياسية فقط لضمان التوافق العالي عبر الشاشات والأجهزة اللوحية وتطبيقات الجوال.
- **الحد الأقصى لحجم الملف:** `10MB` كحد أقصى.
- **الأبعاد والقياسات القصوى:** `960x540` بكسل بدقة QHD.

## 3. خدمات التسعير المستقلة: الموسمي، عطلة نهاية الأسبوع، والذروة الديناميكية

تُتيح المنصة للشركاء تعديل الأسعار في المواسم والأعياد وعطلات نهاية الأسبوع وفق ضوابط حوكمة تمنع المغالاة وتضمن الشفافية مع العملاء.

```
                 ┌───────────────────────────────────────────────┐
                 │  إدارة تسعيرات الذروة والمواسم (Peak Pricing) │
                 └───────────────────────┬───────────────────────┘
                                         │
 ┌───────────────────────────────────────┴───────────────────────────────────────┐
 │                                                                               │
 ▼                                                                               ▼
┌─────────────────────────────────────────────┐ ┌─────────────────────────────────────────────┐
│          تسعيرة المواسم والأعياد            │ │         تسعيرة عطلات نهاية الأسبوع          │
│ • مواسم الزواجات، عيد الفطر، وعيد الأضحى    │ │ • أسعار يومي الخميس والجمعة                │
│ • تطبيق نسبة الزيادة المعتمدة بالمئة (%)    │ │ • تطبيق التسعيرة المباشرة التلقائية          │
└─────────────────────────────────────────────┘ └─────────────────────────────────────────────┘
```

### 3.1 قواعد وحوكمة التعديلات الموسمية للأسعار
1. **التقديم المسبق لطلبات تعديل السعر:** يلتزم المزود برفع طلب تعديل أسعار الموسم قبل بدء الموسم بـ **14 يوماً** على الأقل.
2. **سقف الزيادة القصوى المسموح بها:** تحديد حد أقصى للزيادة بقرار الإدارة العامة منعاً للمغالاة التجارية.
3. **عدم المساس بالحجوزات المعتمدة سابقاً:** لا تُطبق الأسعار الموسمية الجديدة على الحجوزات الصادرة والمسددة برقم `BKG-YY-XXXXXXXXXX` وفاتورة `INV-YYXXXXXXXXXX` قبل تاريخ اعتماد الزيادة.
4. **الموافقة الإدارية الصريحة:** تتطلب جميع تغييرات الأسعار الموسمية موافقة صريحة من حساب الإدارة العامة (Admin) قبل سريانها في شاشات الحجز المباشر.
