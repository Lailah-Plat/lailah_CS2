# 🗝️ وثيقة التحقق المستمر من الصلاحيات والتحكم بالوصول والعزل الصارم للجلسات
**Continuous Authorization Engine, RBAC/ABAC Access Control, Session Lifecycle & Multi-Tenancy Data Isolation**

---

## 1. محرك التحقق المستمر من الصلاحيات (Continuous Authorization Engine - CAE)

يُغطي **محرك التحقق المستمر من الصلاحيات** مراقبة وتقييم صلاحيات المستخدم مع كل طلب (API Request) وفي كل شاشة بالواجهة الأمامية للتحقق من هوية وصلاحية المستخدم النشط قبل إتاحة قراءة أو تعديل البيانات.

```
                  ┌───────────────────────────────────────────┐
                  │   محرك التحقق المستمر من الصلاحيات (CAE)  │
                  └─────────────────────┬─────────────────────┘
                                        │
     ┌──────────────────────┬───────────┴───────────┬──────────────────────┐
     ▼                      ▼                       ▼                      ▼
┌─────────┐            ┌─────────┐             ┌─────────┐            ┌─────────┐
│ التحقق  │            │ فحص     │             │ فحص     │             │ التحقق  │
│ من الرمز│            │ الدور   │             │ العزل   │             │ الحرج   │
│ JWT Token│           │ RBAC    │             │ ABAC    │             │ OTP/MFA │
└─────────┘            └─────────┘             └─────────┘            └─────────┘
```

## 2. مصفوفة التحكم بالوصول المبنية على الأدوار والخصائص (RBAC / ABAC Matrix)

تُطبق المنصة نموذجاً مزدوجاً يدمج **التحكم بالوصول القائم على الدور (RBAC)** و**التحكم بالوصول القائم على الخصائص والعزل (ABAC)** لضمان الحماية التامة:

```
+-----------------------------------------------------------------------------------+
|                        Lailah Comprehensive Access Control Matrix                 |
+-----------------------------------------------------------------------------------+
|  1. Super Admin ('admin'): الوصول الكامل الشامل لجميع الأقسام والإعدادات العامة. |
|  2. Finance Officer ('admin'): إدارة المالية، الفواتير INV، الاعتمادات، وصرف REV.  |
|  3. Partner / Provider ('provider'): إدارة قاعاته، خدماته، طلباته BKG/SRV فقط. |
|  4. Field Staff ('provider_staff'): تشغيل الفعاليات، وممنوع من المالية تماماً.   |
|  5. Customer ('customer'): استكشاف وتصفح القاعات وحجزها ومتابعة سجلاته الشخصية.  |
+-----------------------------------------------------------------------------------+
```

### 2.1 جدول مصفوفة الصلاحيات التفصيلية بالمنظومة

| الوظيفة / الشاشة بالمنصة | مدير الإدارة (Admin) | الضابط المالي (Finance) | الشريك (Provider) | طاقم المزود الميداني | العميل (Client) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **استكشاف القاعات والخدمات العام** | ✅ متاح | ✅ متاح | ✅ متاح | ✅ متاح | ✅ متاح |
| **إصدار حجز جديد (`BKG-YY-XXXXXXXXXX`)** | ❌ غير متاح | ❌ غير متاح | ❌ غير متاح | ❌ غير متاح | ✅ متاح |
| **لوحة تشغيل القاعات والطلبات الخاصة** | ✅ متاح | ✅ متاح | ✅ متاح (قاعاته فقط) | ✅ (ميداني) | ❌ محظور |
| **اعتماد القاعات والخدمات المعلقة** | ✅ متاح | ✅ متاح | ❌ محظور | ❌ محظور | ❌ محظور |
| **عرض التقارير والعمولات المجمعة** | ✅ متاح | ✅ متاح | ✅ (خاص به فقط) | ❌ **محظور تماماً** | ❌ محظور |
| **عرض الفاتورة الضريبية الموحدة `INV`** | ✅ متاح | ✅ متاح | ❌ **محظور تماماً** | ❌ **محظور تماماً** | ✅ (فاتورته فقط) |
| **قسم الإعدادات العامة للنظام** | ✅ متاح | ❌ محظور | ❌ **محظور تماماً** | ❌ **محظور تماماً** | ❌ محظور |

## 3. حظر الإعدادات والفواتير الضريبية الموحدة في لوحة تحكم المزود (Dashboard Access Control)

تُطبق القاعدة التالية بشكل صلب في الواجهات الأمامية والنقاط الخلفية لـ APIs:

```
[محاولة دخول رابط بـ role: 'provider'] ──► [فحص التبويب المزار]
                                                 │
       ┌─────────────────────────────────────────┴─────────────────────────────────────────┐
       ▼                                                                                   ▼
(التبويب: "الإعدادات العامة" أو "الفاتورة الضريبية الموحدة")                       (أي تبويب تشغيلي آخر مخصص للمزود)
       │                                                                                   │
       ▼                                                                                   ▼
[حظر الوصول الفوري وتوجيه الحساب للوحة التحكم الرئيسية]                                 [السماح بالعرض بناءً على providerId]
```

1. **حظر صفحة الإعدادات العامة (General Settings):** يُمنع المزود نهائياً من تصفح أو تعديل الإعدادات السيادية للنظام (إعدادات الدفع الموحدة، شروط المنصة، إعدادات النظام العامة)، ويُخفى التبويب تلقائياً عند كشف رتبة المستخدم كـ `provider`.
2. **حظر الفاتورة الضريبية الموحدة (Unified Tax Invoice):** يُحظر عرض أو إصدار الفاتورة الضريبية الموحدة للمزود واقتصارها فقط على حساب الإدارة العامة (`Admin`).
3. **التأكيد البرمجي:** إعادة توجيه أي محاولة كتابة يدويّة للرابط إلى الصفحة الرئيسية للوحة تحكم المزود.

## 4. قواعد العزل الصارم متعدد المستأجرين (Multi-Tenancy Isolation Rules)

1. **تصفية بيانات المزودين (`Provider Multi-Tenancy`):**
   - مطابقة المعرف الفريد للمزود (`providerId`) في كافة استعلامات قاعدة البيانات والـ React State.
   - حظر تام لظهور أي بيانات تخص شركاء أو موفرين آخرين برادارات العمليات أو التقارير المالية.
2. **سرية وحماية بيانات العملاء (`Client Multi-Tenancy`):**
   - حظر إظهار أي حجوزات `BKG` أو طلبات `SRV` أو فواتير `INV` لأي عميل إلا إذا كانت مرتبطة بحسابه الشخصي المباشر عبر `customerId`.
3. **آلية التحكم بالهوية المعروضة للعملاء (`showProviderToCustomers`):**
   - إظهار الاسم الرسمي للمزود أو الاسم المستعار المقترن بناءً على إعدادات الشريك المعتمدة.

## 5. دورة حياة الجلسات وتأمين الـ Tokens (Session Lifecycle & Revocation)

- **مدة صلاحية الـ Access Token:** ينتهي الرمز القصير كل **15 دقيقة** ويتطلب تجديداً صامتاً عبر `Refresh Token`.
- **مدة صلاحية الـ Refresh Token:** يُحفظ بملفات كوكيز مشفرة ومحميّة بخاصية `HttpOnly; Secure; SameSite=Strict` لمدة 7 أيام.
- **إلغاء الجلسات الفوري (Instant Session Revocation):** إمكانية إبطال كافة جلسات المستخدم النشطة فوراً من قبل الإدارة العامة عند اكتشاف أي نشاط مشبوه أو تغيير كلمة المرور.
