# 💬 وثيقة الاتصالات، المحادثات المباشرة، الدعم الفني والبريد
**Communication Hub, Live Chat, Support Tickets Engine & Email Notifications**

---

## 1. محرك الرسائل والمحادثات المباشرة (Live Messaging Hub)

تتضمن منصة **ليلة** مركز اتصالات متطور يربط العملاء بالشركاء والإدارة العامة عبر محادثات نصية مباشرة ومحمية.

```
                  ┌───────────────────────────────────────────┐
                  │   مركز الاتصالات والمحادثات المباشرة      │
                  └─────────────────────┬─────────────────────┘
                                        │
           ┌────────────────────────────┼────────────────────────────┐
           ▼                            ▼                            ▼
┌──────────────────────┐    ┌──────────────────────┐    ┌──────────────────────┐
│  محادثة العميل والمزود│    │  محادثة المزود والإدارة│    │  محادثة العميل والإدارة│
│  • استفسارات القاعة   │    │  • الاعتمادات والمالية│    │  • الدعم والشكاوى     │
└──────────────────────┘    └──────────────────────┘    └──────────────────────┘
```

### 1.1 مميزات محرك المحادثات
1. **الربط التلقائي بمرجع الحجز:** إمكانية بدء المحادثة مباشرة من صفحة الحجز (`BKG-YY-XXXXXXXXXX`) أو طلب الخدمة (`SRV-YY-XXXXXXXXXX`).
2. **العزل التام والتشفير:** لا يستطيع أي مزود رؤية محادثات المزودين الآخرين.
3. **تبادل المرفقات:** إرسال واستلام الصور والمستندات بحد أقصى `500KB` للصور.

## 2. نظام تذاكر الدعم الفني والاحتفاظ بالبيانات (Support Tickets Engine & Retention)

تدار تذاكر الدعم الفني والشكاوى والاستفسارات عبر نظام أتمتة موحد:

### 2.1 حالات ودورة حياة التذكرة
1. **إنشاء التذكرة:** تحديد القسم (المالية، الحجوزات، الدعم التقني، الشكاوى)، الموضعة، الشدة (`عادي` | `عاجل` | `حرج`).
2. **المعاملة والردود:** إسناد التذكرة لموظف الدعم المخصص والرد التفاعلي.
3. **إغلاق التذكرة والأرشفة:** تحويل الحالة إلى `مغلقة` فور المعالجة.

### 2.2 سياسة مدة الاحتفاظ بالتذاكر (`TICKET_RETENTION_DAYS`)
- يتيح النظام للإدارة ضبط خيار مدة الاحتفاظ بالتذاكر القديمة الأرشيفية عبر متغير `TICKET_RETENTION_DAYS`.
- يتم التنظيف والتصفية الآلية للتذاكر التي تجاوزت عدد الأيام المحددة للحفاظ على سرعة وأداء قواعد البيانات.

## 3. البريد الإلكتروني والإشعارات اللحظية (Email & System Signals)

### 3.1 الإشعارات عبر البريد الإلكتروني
- **تأكيد الحجز والفاتورة:** إرسال ملخص الحجز متضمناً رقم الحجز `BKG` والفاتورة `INV` للعميل والمزود.
- **تحديثات الاعتماد:** إشعار المزود فور موافقة الإدارة على اعتماد قاعته أو خدمته.
- **التنبيهات المالية:** إشعار بتحويل المستحقات أو صدور التقارير المالية.

### 3.2 إشارات التزامن المباشرة بالنظام (System Synchronization Events)
تستخدم المنصة أحداث متصفح مخصصة لضمان تحديث الواجهات فورياً دون الحاجة لإعادة تحميل الصفحة:
1. `settingsUpdated`: تُطلق فور تعديل الإعدادات أو تحديث بيانات المزود والهوية.
2. `providerDataSynced`: تُطلق فور إتمام التزامن مع قاعدة البيانات السحابية (`/api/users/profile-sync`).
3. `storage`: تُطلق لمزامنة التغيرات بين التبويبات المفتوحة بالمتصفح.
