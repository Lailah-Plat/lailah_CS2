# 🔒 وثيقة العزل الصارم، الأمان، وإدارة الصلاحيات
**Multi-Tenancy Architecture, Data Isolation & Access Security Rules**

---

## 1. قواعد العزل البرمجي الصارم لبيانات الشركاء والعملاء (Multi-Tenancy Strict Data Isolation)

تُطبق منصة **ليلة** سياسة العزل الصارم التام (Strict Multi-Tenancy Enforcement) لمنع أي تسريب أو تداخل للبيانات بين الشركاء والمزودين المختلفين، أو بين حسابات العملاء الشخصية.

```
                  ┌───────────────────────────────────────────┐
                  │    محرك العزل البرمجي (Tenancy Isolator)  │
                  └─────────────────────┬─────────────────────┘
                                        │
           ┌────────────────────────────┴────────────────────────────┐
           ▼                                                         ▼
┌──────────────────────────────────────┐  ┌──────────────────────────────────────┐
│  لوحة مزود الخدمة (Provider Tenant)  │  │   حساب العميل (Customer Tenant)      │
│  • فلترة تلقائية حسب providerId      │  │   • سرية تامة حسب customerId         │
│  • إخفاء تام للسجلات الخارجية        │  │   • حظر الاطلاع على بيانات الآخرين   │
└──────────────────────────────────────┘  └──────────────────────────────────────┘
```

### 1.1 قواعد العزل في لوحة تحكم المزود (Provider Workspace)
1. **تصفية البيانات الإجبارية:** عند تسجيل دخول أي مستخدم برتبة مزود (`role: 'provider'`)، يتم تصفية كل من:
   - قائمة القاعات والأماكن المملوكة.
   - قائمة الخدمات المضافة والخدمات المساندة.
   - جميع الحجوزات وطلبات الخدمات الواردة.
   - المؤشرات المالية والإحصائيات والرسوم البيانية والمبيعات.
   - الفواتير، الإيرادات، والمصروفات الخاصة به.
   - تذاكر الدعم الفني والمحادثات المباشرة مع العملاء.
2. **آلية الفلترة الفنية:**
   - المطابقة عبر المعرف الفريد للمزود (`providerId` أو `dbId` أو `id`).
   - المطابقة الاحتياطية عبر الاسم التجاري المسجل كخط دفاع إضافي.
3. **الحظر الفوري للسجلات الخارجية:** يمنع النظام برمجة أي استعلام يتيح لمزود رؤية أي عنصر مملوك لمزود آخر تحت أي ظرف.

### 1.2 قواعد الخصوصية وحماية بيانات العميل (Client Data Privacy)
1. **سرية الحساب:** يُحظر عرض الحجوزات أو الفواتير أو تذاكر الدعم الخاصة بالعميل لأي طرف آخر، وتقتصر التصفية في واجهته على `customerId` النشط بنظامه.
2. **التحكم بإظهار اسم المزود للعملاء (`showProviderToCustomers`):**
   - عندما يقدم المزود خدماته، يتيح النظام له خيار تحديد هل يرغب بإظهار اسم منشأته التجاري المعتمد للعملاء أم استخدام اسم مستعار/اسم مستخدم اختياري.
   - عند **تفعيل الخيار (`true`)**: يُعرض آلياً نفس اسم المزود التجاري المعتمد في الواجهات ويُعطل تغيير الاسم المستعار.
   - عند **إلغاء التفعيل (`false`)**: يُتاح للمزود إدخال اسم مستعار اختياري (مثل: "مزود خدمة ممتاز") ليظهر بدلاً من اسمه التجاري.

## 2. قواعد حظر الإعدادات والفواتير الضريبية الموحدة في لوحة المزود (Dashboard Access Control)

يحتوي النظام على حظر أمني وهيكلي محكم على الخيارات والتأكيدات التالية لمنع وصول المزود (`role: 'provider'`) إليها:

| الخيار المحظور على المزود | سبب الحظر والضوابط الأمنية | التصرف البرمجي عند محاولة الوصول |
| :--- | :--- | :--- |
| **قسم الإعدادات العامة (General Settings)** | الإعدادات العامة تحتوي على مفاتيح الدفع السيادية وشروط المنصة والإعدادات الأمنية العامة الشاملة. | إخفاء التبويب تماماً من القائمة الجانبية، وإعادة توجيهه تلقائياً للصفحة الرئيسية إذا كتب الرابط يدوياً. |
| **الفاتورة الضريبية الموحدة (Unified Tax Invoice)** | الفاتورة الضريبية الموحدة تصدر حصرياً من حساب الإدارة العامة (`Admin`) شاملة العمولات الكلية للمنصة. | حظر عرض أو تحميل الفاتورة الضريبية الموحدة للمزود وإخفاء الأزرار الموصلة إليها. |

---

## 3. قواعد اعتماد القاعات والخدمات المستقلة من الإدارة (Asset Approval Workflow)

لتأمين جودة ومعايير العروض المدرجة في منصة "ليلة"، يخضع رفع القاعات والخدمات لسلسلة الاعتمادات التالية:

1. **حالة التعليق الإجبارية عند الإضافة (`Pending Approval`):**
   - فور قيام المزود بإنشاء قاعة جديدة أو إضافة خدمة مساندة مستقلة، تُسجل حالتها تلقائياً كـ `pending` (بانتظار اعتماد الإدارة).
2. **الحظر التام للعرض العام قبل الاعتماد:**
   - يمنع خادم المنصة عرض أو إدراج أي قاعة أو خدمة بوضع `pending` في واجهات العملاء العامة عبر جميع متصفحات الويب والتطبيقات الذكية.
3. **الصلاحية الحصرية للإدارة (`Admin Approval`):**
   - تنحصر صلاحية الموافقة وتحويل الحالة إلى `approved` (معتمدة ونشطة) في لوحة تحكم الإدارة العامة فقط بعد مراجعة الصور، الأبعاد، المواصفات، والأسعار.
