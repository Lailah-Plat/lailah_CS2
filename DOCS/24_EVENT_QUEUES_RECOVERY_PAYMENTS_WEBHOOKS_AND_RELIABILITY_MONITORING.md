# ⚡ وثيقة نظام طوابير الأحداث الممتدة، التعافي، بوابات الدفع ورصد الموثوقية
**Event Queue Architecture, Auto-Recovery Engine, Payment Gateways & System Reliability Monitoring**

---

## 1. نظام طوابير الأحداث الممتدة وآلية التعافي الذاتي (Extended Event Queue & Auto-Recovery)

تعتمد المنظومة على معمارية الأحداث الموجهة (Event-Driven Architecture) مع طوابير الرسائل الممتدة لضمان تنفيذ المعاملات ومعالجة البيانات دون أي فقدان حتى عند وجود ضغط عالٍ أو انقطاع طارئ في الخدمات الخارجية.

```
                  ┌───────────────────────────────────────────┐
                  │    محرك طوابير الأحداث والرسائل (Event Bus) │
                  └─────────────────────┬─────────────────────┘
                                        │
     ┌──────────────────────┬───────────┴───────────┬──────────────────────┐
     ▼                      ▼                       ▼                      ▼
┌─────────┐            ┌─────────┐             ┌─────────┐            ┌─────────┐
│ الأحداث │            │  طابور  │             │  طابور  │             │ طابور  │
│  الحية  │            │ الحجوزات│             │ الإشعارات│             │ المالية │
└─────────┘            └─────────┘             └─────────┘            └─────────┘
```

### 1.1 آلية معالجة التعافي والرسائل الميتة (Dead-Letter Queue & Auto-Recovery)
1. **طابور الرسائل الأساسي (Main Event Queue):** استقبال أحداث الحجوزات `BKG` والطلبات `SRV` والرسائل المباشرة.
2. **محاولات إعادة الإرسال الآلية (Exponential Backoff Retries):** في حال فشل الاتصال مع نظام خارجي (مثل بوابة الدفع أو ZATCA)، يُعيد النظام المحاولة حتى **5 مرات** بمهلة زمنية متضاعفة.
3. **طابور الرسائل الميتة (Dead-Letter Queue - DLQ):** نقل أحداث المعاملات الفاشلة بعد استنفاد المحاولات لحافظة DLQ الآمنة.
4. **محرك التعافي التلقائي (Auto-Recovery Worker):** تشغيل العمالة السحابية الدورية لإعادة المعالجة الآلية فور استعادة الخدمة المستهدفة بدون أي تدخل بشري.

## 2. التكامل المعياري مع بوابات الدفع ومعالجة الـ Webhooks (Payment Gateways & Webhooks Engine)

تُوفر المنصة ربطاً آمناً وموثوقاً مع بوابات الدفع الإلكترونية المعتمدة في المملكة (مدى، الفيزا/الماستركارد، و Apple Pay) وفق أعلى معايير الأمان والحماية PCI-DSS.

```
[إتمام الدفع بالعميل] ──► [إرسال مشفر لبوابة الدفع] ──► [تأكيد المعاملة بالبنك]
                                                               │
                                                               ▼
[تحديث الحجز BKG وإصدار الفاتورة INV] ◄── [إشارة الـ Webhook المعتمدة]
```

### 2.1 حوكمة واستقبال إشارات الـ Webhook
1. **التحقق من التوقيع الرقمي (Webhook Signature Validation):** التحقق من صحة مصدر إشارة الـ Webhook لمنع الهجمات الإلكترونية أو المحاولات الاحتيالية.
2. **منع التكرار المالي (Idempotency Key Enforcement):** استخدام المفتاح الفريد لكل معاملة لمنع تكرار قيد الحساب أو الخصم المزدوج.
3. **التأكيد اللحظي للحجز والسند:**
   - تغيير حالة الحجز فوراً إلى `Confirmed` برقم الحجز القياسي `BKG-YY-XXXXXXXXXX`.
   - إصدار وتوثيق الفاتورة الضريبية الصادرة `INV-YYXXXXXXXXXX` وإتاحتها للتنزيل بصيغة PDF.

## 3. مؤشرات أداء الموثوقية والرصد التشغيلي (Operational Reliability KPIs & Technical Monitoring)

تُتابع منصة "ليلة" الجاهزية الفنية للأنظمة والسيرفرات على مدار الساعة عبر مصفوفة مؤشرات أداء الموثوقية:

```
+-----------------------------------------------------------------------------------+
|                     Lailah System Reliability & Health Dashboard                   |
+-----------------------------------------------------------------------------------+
|  [🟢 نسبة التوافر Uptime: 99.99%]  [⚡ زمن الاستجابة Latency: 120ms]                |
|  [🛡️ نسبة الخطأ Error Rate: <0.01%] [🔄 سرعة معالجة الـ Webhook: 85ms]           |
+-----------------------------------------------------------------------------------+
```

### 3.1 جدول مؤشرات الموثوقية الفنية (Reliability Metrics Matrix)

| المؤشر الفني (Technical Metric) | المعيار والهدف الأقصى المسموح به | الإجراء عند التجاوز |
| :--- | :--- | :--- |
| **نسبة توافر المنظومة (System Uptime)** | **99.99%** على مدار الشهر | إطلاق الإنذار العاجل لمهندسي DevOps وتفعيل السيرفرات الاحتياطية. |
| **زمن استجابة الـ API (Latency)** | أقل من **150ms** لـ 95% من الطلبات | التوسع الذاتي المتوازي (Auto-Scaling) للـ Cloud Run Containers. |
| **معدل أخطاء النظام (Error Rate)** | أقل من **0.05%** من إجمالي الطلبات | تشخيص فوري للسجلات واستدعاء نظام التعافي الذاتي. |
| **زمن معالجة الفاتورة `INV` والربط** | أقل من **500ms** لتوليد PDF وتحديث ZATCA | إعادة التوجيه لطابور المعالجة الخلفية المستقل. |
