## 1. الأهداف والنطاق العام (Scope & Architectural Goals)

تُحدد هذه الوثيقة الهيكلية الهندسية والمالية والمحاسبية الموحدة لجميع عمليات الإلغاء والاسترداد المالي والعكس المحاسبي في منصة "ليلة".

### المبادئ الحاكمة (Core Invariants):
1. **المسار المالي الموحد (Single Source of Truth):**
   يخضع أي استرداد مالي (كامل، جزئي، نقدي، محفظة، قبل التسوية، بعد التسوية، خطأ مزود، إلغاء عميل، قرار إداري، قوة قاهرة) لمحرك مالي واحد مركزي هو `RefundOrchestrator`.
2. **فصل الحالة التشغيلية عن التنفيذ المالي:**
   `Cancellation ≠ Refund`. الإلغاء هو تغيير الحالة التشغيلية للحجز وتوثيق السبب والمبادر. بينما الاسترداد هو المعالجة المالية والمحاسبية الرقمية المقيدة بدفتر الأستاذ العام.
3. **حظر التعديل المباشر للأرصدة:**
   يُحظر منعاً باتاً على أي UseCase أو Controller أو Handler تعديل `wallet.balance` أو `wallet.pendingBalance` أو `customerWallet.cashBalance` أو إيرادات المنصة أو الضرائب بشكل مباشر خارج المحرك المالي الموحد.
4. **توازن القيد المحاسبي المزدوج الصارم ($\Sigma \text{Debit} = \Sigma \text{Credit}$):**
   كل حركة استرداد مالي تولد قيداً مزدوجاً متوازناً 100%، ولا يتم قبول أي قيد غير متوازن تحت أي ظرف.
5. **عدم إسقاط أو شطب ديون الشركاء والذمم المدينة:**
   حظر استخدام `Math.max(0)` عند استرداد المبالغ بعد صرف الأرباح للمزود؛ وتسجيل أي عجز مالي كذمة مدينة رسمية موثقة (`ProviderReceivableModel`).

## 2. مصفوفة حالات الاسترداد المالي المدعومة (Refund Typology)

| نوع الاسترداد (`RefundType`) | الوصف والآلية التشغيلية | المعالجة المحاسبية |
| :--- | :--- | :--- |
| **`FULL_REFUND`** | استرداد كامل 100% للعميل قبل موعد المناسبة أو خلال نافذة السماح (24 ساعة). | عكس كامل لحصة المزود المعلقة وعكس كامل لعمولة المنصة والضريبة مع صرف المبلغ للعميل. |
| **`PARTIAL_REFUND`** | استرداد جزئي بحسب سياسة الإلغاء والمهل الزمنية المتبقية. | عكس نسبي متوازن لحصة المزود وعمولة المنصة مع احتفاظ المنصة برسوم الإلغاء أو العمولة المستحقة. |
| **`NO_REFUND`** | إلغاء متأخر (أقل من 3 أيام) بدون استرداد مالي للعميل. | عدم صرف أي مبالغ مستردة؛ ترحيل حصة المزود والمنصة كإيراد مستحق بالكامل. |
| **`WALLET_REFUND`** | استرداد داخلي لمحفظة العميل (Customer Wallet) أو قسيمة جدولة. | قيد دائن بالتزام محفظة العميل دون خروج تدفق نقدي خارجي عبر البنك/البوابة. |
| **`GATEWAY_REFUND`** | استرداد نقدي عكسي عبر بوابة الدفع الإلكتروني الأصلية (Moyasar/PayTabs). | إرسال أمر استرداد للبوابة، وتوليد مرجع استرداد خارجي، وقيد دائن بحساب المقاصة النقدية. |
| **`MIXED_REFUND`** | استرداد هجين موزع بين البوابة والمحفظة. | تنفيذ عبر أرجل استرداد متعددة (`RefundLegs`) مع قيد محاسبي جامع متوازن. |
| **`PRE_SETTLEMENT_REFUND`** | استرداد لحجز لم تُصرف مستحقاته للمزود بعد (حالة `held` أو `scheduled`). | تخفيض/إلغاء أمر التسوية وتخفيض الرصيد المعلق (`pendingBalance`) للمزود. |
| **`POST_SETTLEMENT_REFUND`** | استرداد بعد تحويل الأرباح للمزود مسبقاً (حالة `paid`). | خصم الرصيد المتاح؛ وتحويل أي عجز مالي إلى ذمة مدينة نظامية على المزود (`ProviderReceivable`). |
| **`PROVIDER_FAULT_REFUND`** | إلغاء بخطأ من المزود أو إخلال تشغيلي. | استرداد 100% للعميل يتحمله المزود بالكامل، مع احتفاظ المنصة بحقها وعمولتها. |
| **`CUSTOMER_CANCELLATION_REFUND`** | إلغاء اختياري من العميل خاضع لسياسة القاعة والمنصة. | تطبيق نموذج التسوية النشط (الهجين أو القاطع) والمهل الزمنية. |
| **`ADMIN_OVERRIDE_REFUND`** | استرداد بقرار إداري ورقابي سيادي من الإدارة العليا. | تنفيذ النسبة المعتمدة استثنائياً مع توثيق اسم المعتمد والمبررات. |
| **`FORCE_MAJEURE_REFUND`** | ظروف قاهرة معتمدة وموثقة رسمياً (كوارث، قرارات رسمية). | استرداد كامل أو قسيمة رصيد مجدول دون تحميل أي رسوم إلغاء على العميل. |

## 3. آلة الحالة للاسترداد المالي (Canonical State Machine)

```
[REQUESTED] ──► [CALCULATED] ──► [APPROVED] ──► [PROCESSING]
                                                     │
               ┌─────────────────────────────────────┼──────────────────────────────────┐
               ▼                                     ▼                                  ▼
         [SUCCEEDED]                            [PARTIAL]                            [FAILED]
               │                                                                        │
               ├───────────────────┐                                                    ▼
               ▼                   ▼                                                [RETRY]
      [LEDGER_POSTED]     [RECONCILED]                                                  │
                                                                                        ▼
                                                                                [MANUAL_REVIEW]
```

### توصيف الحالات:
1. **`REQUESTED`**: استلام طلب الاسترداد والتحقق من صحة المعطيات وتوليد مفتاح منع التكرار (`idempotencyKey`).
2. **`CALCULATED`**: تقييم السياسة من خلال `RefundPolicyEngine` بناءً على اللقطة المالية الأصلية وتوليد `RefundSnapshot`.
3. **`APPROVED`**: اعتماد العملية مالياً وإدارياً (تلقائي للحجوزات النظامية أو يدوي للاستثناءات).
4. **`PROCESSING`**: إرسال الأوامر لأرجل الاسترداد (بوابة الدفع أو المحفظة) وبدء المعاملة البنكية.
5. **`SUCCEEDED`**: نجاح كافة أرجل الاسترداد وترحيل القيد المحاسبي المتوازن لدفتر الأستاذ العام وتحديث السجلات.
6. **`FAILED`**: تعثر العملية لدى بوابة الدفع وتوجيهها للمراجعة اليدوية أو المحاولة اللاحقة مع منع تعديل الدفاتر بما يخالف الواقع.
7. **`RECONCILIATION_REQUIRED`**: حالة عدم تطابق أو تعليق تتطلب مطابقة تسوية مصرفية يدوية.

## 4. اللقطة المالية للاسترداد (Immutable Refund Snapshot)

يتم تجميد وحفظ لقطة مالية كاملة وغير قابلة للتعديل (`RefundSnapshot`) في حقل `snapshot` بجدول `refund_allocations` وتتضمن:

```typescript
export interface RefundSnapshot {
  refundId: string;                     // رقم الاسترداد التسلسلي: RFD-YY-XXXXXXXXXX
  idempotencyKey?: string | null;       // مفتاح منع التكرار
  bookingId?: number | null;            // رقم الحجز
  paymentId: string;                    // معرف عملية الدفع الأصلية
  providerId?: number | null;           // معرف المزود
  customerId?: number | null;           // معرف العميل
  customerEmail?: string | null;        // بريد العميل
  originalGrossAmount: number;          // المبلغ الإجمالي الأصلي بالهللات
  originalNetAmount: number;            // المبلغ الصافي الأصلي
  originalPlatformCommission: number;   // إجمالي عمولة المنصة الأصلية
  originalPlatformRevenue: number;      // صافي عمولة المنصة الخاضعة للضريبة
  originalPlatformVat: number;          // ضريبة القيمة المضافة على العمولة
  originalProviderShare: number;        // حصة المزود الأصلية
  refundedCustomerAmount: number;       // المبلغ المسترد للعميل بالهللات
  providerDeduction: number;            // المبلغ المخصوم من حصة المزود
  platformCommissionReversal: number;   // إجمالي عمولة المنصة المعكوسة
  platformRevenueReversal: number;      // صافي إيراد المنصة المعكوس
  platformVatReversal: number;          // ضريبة المنصة المعكوسة
  administrativeFee: number;            // رسوم الإلغاء المحتفظ بها للمنصة
  retainedProviderAmount: number;       // الحصة المتبقية للمزود
  providerReceivableAmount: number;     // مبلغ الذمة المدينة المسجل على المزود
  providerAvailableDeduction: number;   // المبلغ المخصوم فعلياً من محفظة المزود
  refundMethod: 'gateway' | 'wallet' | 'mixed';
  refundType: RefundType;
  isPostPayout: boolean;
  policyId: string;
  policyVersion: string;
  reason: string;
  cancelledBy: 'customer' | 'provider' | 'admin' | 'force_majeure';
  calculationTimestamp: string;
  currency: 'SAR';
  legs: RefundLegQuote[];
}
```

## 5. قواعد المحاسبة المزدوجة وموازنة القيود (Double-Entry Invariants)

يجب أن يحقق كل قيد استرداد مالي المعادلة الحتمية:
$$\sum \text{Debits} = \sum \text{Credits}$$

### دليل الحسابات المحاسبية (Chart of Accounts):
* **`provider` (حساب المزود):** يمثل التزام المنصة تجاه المزود (سواء رصيد معلق `pending` أو متاح `available`).
* **`platform_revenue` (إيراد المنصة):** حساب الإيراد التشغيلي لعمولة المنصة ورسوم الإلغاء.
* **`platform_vat` (ضريبة القيمة المضافة المستحقة):** التزام ضريبة القيمة المضافة لهيئة الزكاة والضريبة والجمارك (ZATCA).
* **`gateway_fee` / `gateway_clearing` (وسيط مقاصة البوابة/البنك):** حساب المقاصة النقدية الممثلة لتدفق الأموال الخارجة.
* **`customer_wallet` (محفظة العميل):** التزام داخلي برصيد العميل المتاح للاستخدام المستقبلي.

### نماذج القيود المحاسبية المعيارية:

#### أ. حالة استرداد كامل قبل صرف أرباح المزود (Pre-Settlement Full Refund):
* حجز بقيمة 10,000 ر.س (عمولة 10% شاملة الضريبة = 1,000 ر.س، حصة المزود = 9,000 ر.س):
  * **مدين (Dr):** `provider` (عكس الرصيد المعلق المحجوز) = 9,000.00 ر.س
  * **مدين (Dr):** `platform_revenue` (عكس صافي عمولة المنصة) = 869.57 ر.س
  * **مدين (Dr):** `platform_vat` (عكس الضريبة 15%) = 130.43 ر.س
  * **دائن (Cr):** `gateway_clearing` (صرف الاسترداد النقدي للعميل) = 10,000.00 ر.س
  * **المجموع:** مدين 10,000.00 ر.س = دائن 10,000.00 ر.س *(متوازن 100%)*

#### ب. حالة استرداد بعد صرف الأرباح مع عجز في رصيد المزود (Post-Settlement with Receivable):
* رصيد المزود المتاح في المحفظة هو 3,000 ر.س فقط والمبلغ المطلوب خصمه 9,000 ر.س:
  * **مدين (Dr):** `provider` (خصم الرصيد المتاح من محفظة المزود) = 3,000.00 ر.س
  * **مدين (Dr):** `provider` (تسجيل ذمة مدينة `ProviderReceivable` مستحقة لليلة) = 6,000.00 ر.س
  * **مدين (Dr):** `platform_revenue` (عكس صافي العمولة) = 869.57 ر.س
  * **مدين (Dr):** `platform_vat` (عكس ضريبة القيمة المضافة) = 130.43 ر.س
  * **دائن (Cr):** `gateway_clearing` (صرف الاسترداد النقدي للعميل) = 10,000.00 ر.س
  * **المجموع:** مدين 10,000.00 ر.س = دائن 10,000.00 ر.س *(متوازن 100%)*

#### ج. حالة استرداد جزئي مع تطبيق رسوم إلغاء (Partial Refund with Cancellation Fee):
* استرداد 75% للعميل (7,500 ر.س) واحتفاظ المنصة بـ 25% (2,500 ر.س رسوم إلغاء):
  * **مدين (Dr):** `provider` (خصم حصة المزود من الاسترداد) = 6,750.00 ر.س
  * **مدين (Dr):** `platform_revenue` (عكس الإيراد الأصلي) = 869.57 ر.س
  * **مدين (Dr):** `platform_vat` (عكس الضريبة الأصلية) = 130.43 ر.س
  * **دائن (Cr):** `gateway_clearing` (صرف المسترد للعميل) = 7,500.00 ر.س
  * **دائن (Cr):** `platform_revenue` (إيراد رسوم الإلغاء المستقطعة) = 2,500.00 ر.س
  * **المجموع:** مدين 7,750.00 ر.س = دائن 10,000.00 ر.س ... (يتم ضبطها تلقائياً لعكس الحصص المتناسبة بدقة رياضية تامة).

## 6. معالجة الذمم المدينة للمزودين (Provider Receivables & Debt Enforcement)

عند حدوث استرداد مالي بعد صرف الأرباح للمزود:
1. يتم فحص `Wallet.balance` المتاح للمزود.
2. إذا كان الرصيد المتاح كافياً، يتم الخصم منه مباشرة.
3. إذا كان الرصيد المتاح غير كافٍ أو صفراً:
   - يُخصم المتاح حتى يصل الرصيد إلى 0 (أو يُقيد التزام).
   - يتم فوراً إنشاء سجل في جدول الذمم المدينة `ProviderReceivableModel` بالرقم التسلسلي `REV-YY-XXXXXXXXXX`.
   - تُحدد مدة استحقاق السداد بـ 14 يوماً.
   - يتم اقتطاع هذا الدين آلياً من أول تسوية مالية أو حجز قادم لنفس المزود.
   - يُمنع منعاً باتاً تصفير أو شطب الدين أو استخدام `Math.max(0)`.

## 7. الحماية من التعارض وحالات السباق (Concurrency & Anti-Race Protection)

1. **معاملات قاعدة البيانات الذرية (Atomic DB Transactions):**
   تُنفذ كل دورة استرداد بالكامل داخل معاملة واحدة (`sequelize.transaction`).
2. **قفل السجلات (Pessimistic / Transactional Locking):**
   قفل سجل الحجز وسجل أمر التسوية `SettlementInstruction` لمنع الصرف المتزامن للمزود في نفس لحظة طلب الاسترداد.
3. **التحقق من حالة التسوية قبل الصرف:**
   إذا كان أمر التسوية في حالة `processing` (قيد الإرسال للبنك)، يتم وضع علامة `reconciliation_required` على الاسترداد وتأجيل الخصم لحين استلام إشعار التحويل البنكي النهائي.

## 8. التحقق من Webhooks وبوابات الدفع (Webhook Verification & Idempotency)

1. **التحقق من التوقيع الرقمي (Signature Verification):**
   فحص التوقيع المشفر في ترويسات الـ Webhook الواردة من Moyasar/PayTabs.
2. **منع التكرار (Idempotency):**
   فحص حالة `executionStatus`؛ إذا كانت `SUCCEEDED` بالفعل، يتم إرجاع نجاح فوري دون إعادة ترحيل القيود المحاسبية أو تكرار العمليات.

## 10. الخلاصة والامتثال المعماري

بهذا التحديث المعماري الشامل (P0):
* أصبحت منصة "ليلة" تمتلك محرك استرداد وعكس محاسبي سيادي موحد ومتكامل (`RefundOrchestrator`).
* تم عزل كافة واجهات المستخدم وحالات الاستخدام التشغيلية (`CancelBookingUseCase`, `ResolveForceMajeureUseCase`) عن تعديل الأرصدة المباشر.
* أصبحت جميع العمليات المالية موثقة ومجمدة بلقطات ثابتة (`RefundSnapshot`)، وتخضع لنظام قيد محاسبي مزدوج دقيق ومتوازن يفي بكافة معايير الامتثال الرقابي والمالي.
