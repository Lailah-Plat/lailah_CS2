## 1. منظومة الدعم الفني وتذاكر الخدمة (Omnichannel Support Core Engine)

تُوفر منصة **ليلة** مركز دعم فني متكامل يعمل على معالجة استفسارات وشكاوى وبلاغات العملاء والشركاء والمزودين عبر قنوات متعددة تشمل المحادثات المباشرة، التذاكر الرسمية، والربط المتقدم مع أنظمة Zoho Desk.

```
                  ┌───────────────────────────────────────────┐
                  │    مركز الدعم الفني والخدمة (Helpdesk)    │
                  └─────────────────────┬─────────────────────┘
                                        │
           ┌────────────────────────────┴────────────────────────────┐
           ▼                                                         ▼
┌──────────────────────────────────────┐  ┌──────────────────────────────────────┐
│        تذاكر العملاء (Clients)       │  │        تذاكر الشركاء (Providers)     │
│   • الاستفسار عن الحجوزات والمدفوعات  │  │   • طلبات الاعتماد وتحديث البيانات   │
│   • الشكاوى وبلاغات الجودة           │  │   • التسويات المالية والتحويلات      │
│   • الاسترجاع وتعديل التواريخ        │  │   • الدعم الفني للوحة التحكم ERP     │
└──────────────────────────────────────┘  └──────────────────────────────────────┘
```

## 2. درجات الأولوية واتفاقيات مستوى الخدمة (SLA & Severity Matrix)

تُصنف تذاكر الدعم الفني فور إنشائها بناءً على درجة الأهمية وتأثيرها التشغيلي مع الالتزام باتفاقية مستوى الاستجابة والحل المحددة آلياً:

| مستوى الأهمية (Severity Level) | وصف الحالة والأثر التشغيلي | وقت الاستجابة الأولى (First Response) | وقت الحل الأقصى (Resolution SLA) |
| :--- | :--- | :--- | :--- |
| **حرجة جداً (Critical - P1)** | تعطل عملية الدفع بالكامل أو مشكلة طارئة أثناء تنفيذ المناسبة بقاعة الحجز. | **خلال 15 دقيقة** | **ساعة واحدة (1 Hour)** |
| **عالية (High - P2)** | إلغاء حجز مؤكد `BKG` أو خلل في احتساب الفاتورة الضريبية `INV`. | **خلال 30 دقيقة** | **4 ساعات (4 Hours)** |
| **متوسطة (Medium - P3)** | استفسار حول حجز، مشكلة في رفع الصور أو تعديل بيانات الملف الشخصي. | **خلال ساعتين (2 Hours)** | **12 ساعة (12 Hours)** |
| **منخفضة (Low - P4)** | اقتراحات عامة، استفسار عن الاشتراكات، أو طلب معلومات إضافية. | **خلال 6 ساعات (6 Hours)** | **24 ساعة (24 Hours)** |

## 3. دورة حياة تذكرة الدعم الفني (Ticketing Lifecycle Workflow)

```
[إنشاء تذكرة جديدة] ──► [تحديد الأولوية والقسم] ──► [تعيين ممثل الدعم تلقائياً]
                                                            │
                                                            ▼
                                           [بدء المباشرة والتواصل مع المستخدم]
                                                            │
                                   ┌────────────────────────┴────────────────────────┐
                                   ▼                                                 ▼
                        [حل المشكلة وإغلاق التذكرة]                        [تصعيد التذكرة للإدارة Escalation]
                                   │                                                 │
                                   ▼                                                 ▼
                        [إرسال تقييم خدمة الدعم]                          [معالجة المدير المالي / التشغيلي]
```

### 3.1 حالات التذكرة المعتمدة (Ticket Status States)
1. **جديدة (`New`):** تم فتح التذكرة وبانتظار التعيين لموظف الدعم.
2. **قيد المعالجة (`In Progress`):** يباشر ممثل الدعم معالجة الطلب والتواصل مع المستخدم.
3. **بانتظار العميل/المزود (`Pending User Input`):** تم طلب مستندات أو معلومات إضافية من المستخدم.
4. **مكتملة ومغلقة (`Resolved / Closed`):** تم حل المشكلة وإصدار سند الحل وتقييم الخدمة.
5. **مُصعّدة (`Escalated`):** تجاوزت اتفاقية SLA وتطلب تدخل الفريق الهندسي أو المالي.

## 4. التكامل المعياري مع نظام Zoho Desk ونظام الاحتفاظ (Integration & Retention Policy)

تتيح المنصة الربط البرمجي الشامل مع نظام **Zoho Desk** لإدارة التذاكر عبر نقاط النهاية السحابية المعتمدة:

### 4.1 آلية الربط المتكامل (Zoho Desk Webhook Synchronization)
- مزامنة كافة تذاكر الخدمة والرسائل بين منصة ليلة ولوحة Zoho Desk آلياً عبر Webhooks.
- ربط بيانات المستخدم بالمعرفات الرسمية (رقم الحجز `BKG-YY-XXXXXXXXXX`، رقم الطلب `SRV-YY-XXXXXXXXXX`، ورقم الفاتورة `INV-YYXXXXXXXXXX`).

### 4.2 سياسة الاحتفاظ بالأرشيف (Support Retention Policy)
- يُحدد النظام مدة الاحتفاظ بالتذاكر المكتملة والمغلقة عبر المتغير المعياري `TICKET_RETENTION_DAYS = 365`.
- أرشفة التذاكر القديمة آلياً بعد مرور عام كامل لحماية خصوصية البيانات وسرعة قواعد البيانات مع حفظ السجل المالي والرقابي بشكل مستقل.

## 5. مصفوفة الصلاحيات والعزل في الدعم الفني (Support Data Isolation Rules)

تلتزم شاشات ووحدات الدعم الفني بقواعد العزل الصارم لبيانات الشركاء والعملاء:

1. **ممثل الدعم للمزود (Provider Support Interface):**
   - استعراض التذاكر الخاصة بالخدمات والقاعات التابعة للمزود الحالي المحددة بـ `providerId` فقط.
   - حظر الاطلاع على تذاكر الشركاء الآخرين أو بيانات الإعدادات العامة للمنصة.
2. **حظر الفاتورة الموحدة والإعدادات العامة:**
   - يقتصر البت في تسويات الفواتير الضريبية الموحدة أو إعدادات النظام السيادية على حساب الإدارة (Super Admin).
