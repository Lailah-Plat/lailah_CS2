# 📊 وثيقة مخططات قاعدة البيانات، النماذج، والتنسيق القياسي للمعرفات
**Database Schema, Entity Models & Standard Serial Number Specifications**

## 1. التنسيق القياسي الإجباري للأرقام التسلسلية والمعرفات (Serial Formats)

تلتزم منصة **ليلة** بتوليد المعرفات التسلسلية لكافة الحركات والأنشطة في المنظومة وفق قواعد صارمة، بحيث يبدأ التسلسل من `0000000001` مع بداية كل سنة ميلادية جديدة (`YY` يمثل أحدث رقمين من السنة، مثل `26` لعام 2026):

```
                                 [نمط المعرفات القياسي]
                                          │
 ┌───────────────────┬────────────────────┼────────────────────┬────────────────────┐
 │  رقم حجز القاعات   │   رقم طلب الخدمة   │   رقم الفاتورة     │   رقم الإيرادات    │
 │ BKG-YY-XXXXXXXXXX │ SRV-YY-XXXXXXXXXX  │  INV-YYXXXXXXXXXX  │ REV-YY-XXXXXXXXXX  │
 └───────────────────┴────────────────────┴────────────────────┴────────────────────┘
```

### 1.1 جدول تفصيلي للمعرفات المعتمدة بالنظام

| الموديل / الحركة | الصيغة البرمجية المعتمدة (Pattern) | مثال لعام 2026 | القواعد والتفاصيل |
| :--- | :--- | :--- | :--- |
| **رقم حجز القاعات** | `BKG-YY-XXXXXXXXXX` | `BKG-26-0000000001` | يبدأ بـ BKG- ثم السنة بـ 2 أرقام ثم واصلة (-) تليها 10 أرقام تسلسلية. |
| **رقم طلبات الخدمات** | `SRV-YY-XXXXXXXXXX` | `SRV-26-0000000001` | يبدأ بـ SRV- ثم السنة بـ 2 أرقام ثم واصلة (-) تليها 10 أرقام تسلسلية. |
| **رقم الفاتورة الصادرة** | `INV-YYXXXXXXXXXX` | `INV-260000000001` | يبدأ بـ INV- ثم السنة مباشرة **بدون واصلة** تليها 10 أرقام تسلسلية. |
| **رقم الإيرادات المالية** | `REV-YY-XXXXXXXXXX` | `REV-26-0000000001` | يبدأ بـ REV- ثم السنة بـ 2 أرقام ثم واصلة (-) تليها 10 أرقام تسلسلية. |
| **رقم المصروفات المالية** | `EXP-YY-XXXXXXXXXX` | `EXP-26-0000000001` | يبدأ بـ EXP- ثم السنة بـ 2 أرقام ثم واصلة (-) تليها 10 أرقام تسلسلية. |

## 2. النماذج الهيكلية وجداول قاعدة البيانات (Entity Relationship Models)

### 2.1 نموذج المستخدمين والشركاء (`User` Model)
يُدار في جدول `users` ويحتوي الحقول التالية:
- `id` (INTEGER / UUID): المعرف الفريد.
- `name` (STRING): الاسم الثلاثي / الاسم التجاري الرسمي للشركة.
- `email` (STRING): البريد الإلكتروني المعتمد.
- `role` (ENUM): نوع الحساب (`admin` | `provider` | `customer`).
- `phone` (STRING): رقم الجوال للتواصل والتحقق.
- `password` (STRING): كلمة المرور المشفّرة بـ bcrypt.
- `commercialRecord` (STRING): رقم السجل التجاري للمنشأة.
- `vatNumber` (STRING): الرقم الضريبي للهيئة العامة للزكاة والدخل.
- `bankName` / `iban` (STRING): البيانات البنكية الرسمية للمستحقات.
- `username` (STRING): اسم المستخدم/الاسم المستعار للعملاء عند تحديد خيار إخفاء اسم المنشأة.
- `showProviderToCustomers` (BOOLEAN): خيار إظهار الاسم التجاري للمزود للعملاء (افتراضي: `true`).
- `status` (STRING): حالة الحساب (`نشط` | `معلق` | `محظور`).

### 2.2 نموذج القاعات والأماكن (`Hall` Model)
يُدار في جدول `halls` ويحتوي الحقول التالية:
- `id` (INTEGER / UUID): معرف القاعة.
- `providerId` (INTEGER): معرف المزود المالك للقاعة (Foreign Key).
- `providerName` (STRING): اسم المزود المعتمد.
- `name` (STRING): اسم القاعة / المكان.
- `city` / `district` (STRING): المدينة والحي.
- `addressDetails` / `latitude` / `longitude` (FLOAT): الموقع الجغرافي الدقيق.
- `capacity` (INTEGER): السعة الاستيعابية القصوى.
- `price` (DECIMAL): سعر الحجز لليوم / الفترة.
- `images` (JSON): مصفوفة روابط صور القاعة وفق المواصفات.
- `videoUrl` (STRING): رابط الفيديو التوضيحي للقاعة.
- `status` (ENUM): حالة الاعتماد (`pending` بانتظار اعتماد الإدارة | `approved` معتمدة ومفتوحة للعملاء | `rejected` مرفوضة).
- `features` (JSON): التجهيزات والمميزات الداخلية.
- `addons` (JSON): قائمة الخدمات المضافة الخاصة بالقاعة مع أسعارها.

### 2.3 نموذج الخدمات المساندة (`Service` Model)
يُدار في جدول `services` ويحتوي الحقول التالية:
- `id` (INTEGER / UUID): معرف الخدمة.
- `providerId` (INTEGER): معرف المزود المقدم للخدمة.
- `providerName` (STRING): اسم المزود المعتمد.
- `title` (STRING): عنوان الخدمة.
- `category` (STRING): الفئة (ضيافة وفندقة، توثيق وتصوير، إضاءة وصوتيات، ديكور وتنسيق، إلخ).
- `price` (DECIMAL): السعر الأساسي للخدمة.
- `description` (TEXT): الشرح والتفاصيل الكاملة.
- `images` (JSON): صور الخدمة.
- `status` (ENUM): حالة اعتماد الإدارة (`pending` | `approved` | `rejected`).

### 2.4 نموذج الحجوزات (`Booking` Model)
يُدار في جدول `bookings` ويحتوي الحقول التالية:
- `id` (STRING): المعرف التسلسلي القياسي `BKG-YY-XXXXXXXXXX`.
- `customerId` (INTEGER): معرف العميل صاحب الحجز.
- `providerId` (INTEGER): معرف مزود القاعة.
- `hallId` (INTEGER): معرف القاعة المحجوزة.
- `eventDate` (DATE): تاريخ المناسبة/الحادثة.
- `guestCount` (INTEGER): عدد الضيوف المتوقع.
- `selectedAddons` (JSON): الخدمات المضافة المختارة من القاعة.
- `totalAmount` (DECIMAL): القيمة الإجمالية للحجز شاملة الضريبة.
- `commissionAmount` (DECIMAL): حصة عمولة منصة ليلة المقتطعة.
- `providerNet` (DECIMAL): صافي مستحقات المزود.
- `invoiceNumber` (STRING): رقم الفاتورة `INV-YYXXXXXXXXXX`.
- `status` (ENUM): حالة الحجز (`مؤكد` | `قيد الانتظار` | `ملغى` | `مكتمل`).

### 2.5 نموذج طلبات الخدمات المساندة (`ServiceRequest` Model)
- `id` (STRING): المعرف القياسي `SRV-YY-XXXXXXXXXX`.
- `customerId` (INTEGER): معرف العميل.
- `providerId` (INTEGER): معرف مزود الخدمة المستقلة.
- `serviceId` (INTEGER): معرف الخدمة المطلوب تنفيذها.
- `eventDate` (DATE): تاريخ تقديم الخدمة.
- `totalAmount` (DECIMAL): السعر المعتمد للطلب.
- `commissionAmount` (DECIMAL): عمولة المنصة المقتطعة.
- `invoiceNumber` (STRING): رقم الفاتورة `INV-YYXXXXXXXXXX`.
- `status` (ENUM): حالة الطلب (`قيد التنفيذ` | `مكتمل` | `ملغى`).

### 2.6 نموذج التعليقات والتقييمات (`Review` Model)
- `id` (INTEGER): معرف التقييم.
- `customerId` / `customerName` (STRING): بيانات العميل التقييمي.
- `targetType` (ENUM): نوع الهدف (`hall` | `service`).
- `targetId` (INTEGER): معرف القاعة أو الخدمة.
- `rating` (INTEGER): التقييم النجمي (1 إلى 5).
- `comment` (TEXT): النص المكتوب والرأي.
- `status` (STRING): حالة المراجعة (`معتمد` | `معلق`).

## 3. الشروط القياسية للوسائط والملفات المرفوعة (Media Specifications)

### 3.1 شروط صور القاعات والخدمات (Images)
1. **الصيغ والامتدادات المدعومة:** `JPEG`, `JPG`, `PNG`, `WebP`.
2. **الحد الأقصى لحجم الملف:** `500KB` للصورة الواحدة (يتم رفض الصور التي تتجاوز هذا الحجم تلقائياً).
3. **الأبعاد والقياسات المسموحة:**
   - **الحد الأدنى للأبعاد:** `960px` عرض × `540px` ارتفاع.
   - **الحد الأقصى للأبعاد:** `1280px` عرض × `720px` ارتفاع.
4. **النسبة المفضلة (Aspect Ratio):** `16:9` عريضة.

### 3.2 شروط مقاطع الفيديو التوضيحية (Videos)
1. **الصيغ المدعومة:** صيغة `MP4` القياسية فقط لضمان التوافق التام عبر مختلف الأجهزة والتطبيقات.
2. **الحد الأقصى للحجم:** `10MB` للمقطع الواحدة.
3. **الأبعاد والقياسات القصوى:** `960px` عرض × `540px` ارتفاع (دقة QHD بنسبة 16:9).
