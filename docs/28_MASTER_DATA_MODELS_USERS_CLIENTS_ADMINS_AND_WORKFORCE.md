# 👥 وثيقة النماذج المعيارية لبيانات المستخدمين، العملاء، الإدارة، والعاملين الميدانيين
**Master Entity Data Models: System Users, Clients, Admin Governance & Provider Workforce**

---

## 1. نموذج بيانات حسابات المستخدمين الموحدة (System User Master Data Entity)

يُمثل هذا النموذج البيانات الأساسية لهوية كل مستخدم يلج منصة **ليلة** بغض النظر عن دوره أو صلاحياته.

```
+-----------------------------------------------------------------------------------+
|                           Unified System User Entity Structure                    |
+-----------------------------------------------------------------------------------+
|  • Identifiers: userId, uuid, email (lowercase), phoneNumber                      |
|  • Authentication: passwordHash (bcrypt), authProvider ('email' | 'otp' | 'sso')  |
|  • Core Role: role ('customer' | 'provider' | 'admin' | 'provider_staff')        |
|  • Account Status: isEmailVerified, isPhoneVerified, isActive, isBanned           |
|  • Security: lastLoginAt, failedLoginAttempts, mfaEnabled, currentSessionToken    |
+-----------------------------------------------------------------------------------+
```

### 1.1 جدول الحقول البرمجية لحساب المستخدم

| الحقل البرمجي (Field Name) | النوع (Data Type) | القيود | الشرح والوظيفة التشغيلية |
| :--- | :--- | :--- | :--- |
| `userId` | `String` | فريد (Primary Key) | المعرف الفريد السحابي للمستخدم في المنظومة. |
| `fullName` | `String` | إجباري، 3-80 حرف | الاسم الكامل المعتمد للمستخدم. |
| `email` | `String` | فريد، صيغة بريد | البريد الإلكتروني المعتمد لتسجيل الدخول والإشعارات. |
| `phoneNumber` | `String` | فريد، صيغة دولية | رقم الجوال المعتمد للتفعيل عبر رمز OTP. |
| `passwordHash` | `String` | bcrypt encrypted | التشفير الآمن لكلمة المرور. |
| `role` | `Enum` | `'customer'` \| `'provider'` \| `'admin'` \| `'provider_staff'` | الدور الأساسي للمستخدم والذي يُحدد الوجهة الافتراضية بعد تسجيل الدخول. |
| `isActive` | `Boolean` | افتراضي: `true` | حالة الحساب النشطة. |

## 2. نموذج بيانات العملاء وسجلات CRM والولاء (Client / Customer Master Data Entity)

يختص هذا النموذج ببيانات عملاء المنصة الذين يقومون ببحث وحجز القاعات والخدمات المساندة.

```
                  ┌───────────────────────────────────────────┐
                  │    نموذج بيانات العميل (Client Entity)     │
                  └─────────────────────┬─────────────────────┘
                                        │
     ┌──────────────────────┬───────────┴───────────┬──────────────────────┐
     ▼                      ▼                       ▼                      ▼
┌─────────┐            ┌─────────┐             ┌─────────┐            ┌─────────┐
│ البيانات│            │ سجل CRM │             │ برنامج  │            │ قائمة   │
│ الشريحة │            │ والحجوزات│             │ الولاء  │            │ المفضلة │
└─────────┘            └─────────┘             └─────────┘            └─────────┘
```

### 2.1 جدول حقول بيانات العميل

| الحقل البرمجي (Field Name) | النوع (Data Type) | القيود والاشتراطات | الشرح والوظيفة |
| :--- | :--- | :--- | :--- |
| `customerId` / `userId` | `String` | فريد (Primary Key) | معرف العميل المرتبط بحسابه الموحد. |
| `loyaltyTier` | `Enum` | `'silver'` \| `'gold'` \| `'diamond'` | مستوى الولاء النشط للعميل (Silver عند التسجيل، Gold بعد 20,000 ريال، Diamond بعد 50,000 ريال). |
| `loyaltyPoints` | `Number` | عدد صحيح أكبر من 0 | رصيد نقاط الولاء الحالي المكتسب من الحجوزات الناجحة (1 نقطة لكل 100 ريال). |
| `favoriteHalls` | `Array<String>` | قائمة بـ `hallId` | قائمة القاعات المفضلة المحفوظة ببروفايل العميل. |
| `totalSpentAmount` | `Number` | إجمالي تراكمي | إجمالي المبالغ المسددة بالحجوزات المكتملة `BKG` والطلبات `SRV` بالفواتير `INV`. |
| `completedBookingsCount`| `Number` | عدد صحيح | عدد الحجوزات والفعاليات المنفذة بنجاح. |

## 3. نموذج بيانات الإدارة العامة والمشرفين (Admin & Governance Master Data Entity)

يُغطي هذا النموذج بيانات قيادة المنصة، المدراء الماليين، ومسؤولي الجودة والاعتماد والدعم الفني.

| الحقل البرمجي (Field Name) | النوع (Data Type) | القيود | الشرح والوظيفة |
| :--- | :--- | :--- | :--- |
| `adminId` / `userId` | `String` | فريد (Primary Key) | معرف حساب الإدارة الموحد. |
| `adminRole` | `Enum` | `'super_admin'` \| `'finance_officer'` \| `'asset_approver'` \| `'support_agent'` | الصلاحية الإدارية الدقيقة بمصفوفة RBAC. |
| `permissions` | `Array<String>` | قائمة صلاحيات | الصلاحيات البرمجية الممنوحة بدقة. |
| `auditLogHistory` | `Array<Object>` | سجل المراجعة | سجل التتبع الأمني لكل إجراء حساس منفذ (تعديل عمولة، اعتماد قاعة، صرف أرباح). |

## 4. نموذج بيانات عاملين وموظفي المزود الميدانيين (Provider Staff / Workforce Entity)

يُغطي هذا النموذج بيانات الطواقم الميدانية والمنظمين التابعين للشركاء والمزودين والمخولين بإدارة الفعاليات ميدانياً.

```
+-----------------------------------------------------------------------------------+
|                     Provider Workforce & Staff Entity Structure                   |
+-----------------------------------------------------------------------------------+
|  • Identifiers: staffId, providerId, hallId (مرفق بقاعة معينة)                     |
|  • Personal Info: staffName, nationalId/Iqama, mobileNumber                       |
|  • Staff Role: 'venue_supervisor' | 'catering_lead' | 'av_tech' | 'event_staff'  |
|  • Field Permissions: checkInGuests, updateBookingStatus, viewShiftSchedule      |
|  • Data Limits: STRICTLY BLOCKED from Financial Reports & Unified Tax Invoices    |
+-----------------------------------------------------------------------------------+
```

### 4.1 جدول حقول بيانات عاملين المزود الميدانيين

| الحقل البرمجي (Field Name) | النوع (Data Type) | القيود والافتراضات | الشرح والوظيفة الميدانية |
| :--- | :--- | :--- | :--- |
| `staffId` | `String` | فريد (Primary Key) | المعرف الفريد لموظف المزود الميداني. |
| `providerId` | `String` | مفتاح أجنبي | المعرف الفريد للمزود المالك المباشر لفرض العزل البرمجي. |
| `hallId` | `String` | مفتاح أجنبي | القاعة أو المنشأة الميدانية المخصص لها الموظف. |
| `staffRole` | `Enum` | `'venue_supervisor'` \| `'catering_lead'` \| `'av_tech'` \| `'event_staff'` | المسمى الوظيفي الميداني (مشرف قاعة، مسؤول ضيافة، فني صوت وإضاءة، طاقم استقبال). |
| `fieldAccessLevel` | `Object` | صلاحيات تطبيق الجوال | السماح بتسجيل الحضور، متابعة دخول الضيوف، وتحديث حالة الحجز `In Progress`. |
| `restrictedAccess` | `Boolean` | ثابت: `true` | **حظر تام** لا يجوز إلغاء قفله للوصول للتقارير المالية أو الفواتير الضريبية الموحدة أو إعدادات النظام. |

## 5. قواعد العزل الصارم ومصفوفة المعرفات القياسية الموحدة

1. **العزل البرمجي للمزود وموظفيه:** تصفية كافة البيانات والاستعلامات بشرط `providerId == currentProviderId`.
2. **سرية بيانات العملاء:** حظر إظهار بيانات العملاء أو حجوزاتهم إلا لحساب العميل النشط `customerId` أو للمزود المباشر المعني بالحجز `BKG-YY-XXXXXXXXXX`.
3. **المعرفات التسلسلية الموحدة (تصفير سنوي من `0000000001`):**
   - **الحجوزات:** `BKG-YY-XXXXXXXXXX`
   - **طلبات الخدمات:** `SRV-YY-XXXXXXXXXX`
   - **الفواتير الصادرة:** `INV-YYXXXXXXXXXX` (بدون واصلة بعد السنة)
   - **الإيرادات المالية:** `REV-YY-XXXXXXXXXX`
   - **المصروفات المالية:** `EXP-YY-XXXXXXXXXX`
