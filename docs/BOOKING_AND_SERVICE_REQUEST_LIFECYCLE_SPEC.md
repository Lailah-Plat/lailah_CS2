# وثيقة المواصفات القياسية لدورة حياة الحجوزات والخدمات المساندة
## Booking & Service Request Lifecycle Specification — Platform Invariant

---

### 1. المبدأ الحاكم والأساس التشغيلي والمالي (Foundational Invariant)

> **القاعدة الحاكمة الأساسية:**
> **"لا تنشأ أي عملية دفع للحجز أو طلب الخدمة قبل موافقة المزود واعتماده للطلب."**
> 
> ```
> Provider Approval  ──►  Payment Eligibility  ──►  Payment Intent  ──►  Verified Payment
> ```

#### المزايا المحققة من تطبيق هذه القاعدة:
1. **تصفير الاستردادات غير الضرورية (Zero Needless Refunds):** منع حدوث أي خصم من بطاقة العميل قبل التحقق من القدرة التشغيلية والقبول الفعلي للمزود.
2. **إلغاء رسوم بوابات الدفع المهدرة (Elimination of Sunk Gateway Fees):** توفير رسوم المعالجة التي تخصمها بوابات الدفع عند كل عملية شحن ثم استرداد.
3. **نظافة وبساطة دفتر الأستاذ (Clean Financial Ledger):** التخلص من قيود الـ Reversal والـ Void غير المبررة.
4. **حماية تجربة العميل (Customer Experience Protection):** تجنب إحباط العميل من تجميد أمواله أو انتظار أيام العمل لاسترداد المبالغ في حال عدم موافقة المزود.

### 3. التمييز بين لقطتي التسعير (Two-Stage Pricing Snapshots)

| المرحلة | اللقطة المالية (Snapshot) | الحقول والمحتوى | القابلية للتعديل |
| :--- | :--- | :--- | :--- |
| **قبل موافقة المزود** | `Pre-Approval Commercial Snapshot` | السعر التقديري الشامل، الخدمات المطلوبة، السعة، التاريخ، الفترات | قابلة للتفاوض أو التعديل عبر طلب التعديل (Amendment) قبل القبول |
| **بعد موافقة المزود** | `Final Payable Snapshot / Payment Quote` | المبلغ الإجمالي النهائي الشامل لضريبة 15%، الخصم المعتمد، تفصيل الضريبة، مهلة السداد الملزمة | **مثبتة بالكامل وغير قابلة للتغيير** إلا بمسار تعديل رسمي معتمد |

### 4. آلة الحالة والحالات المنفصلة (Finite State Machine)

يُمنع دمج الحالات في حالة عامة غامضة مثل `pending`. تُعتمد الحالات المنفصلة التالية:

```
[REQUESTED / AWAITING_PROVIDER_DECISION]
    │
    ├─── المزود يرفض ────────────────────────► [REJECTED] (صفر دفع / صفر استرداد)
    │
    ├─── المزود يتأخر وتنقضي المهلة ──────────► [EXPIRED] (صفر دفع / تحرير الموعد)
    │
    └─── المزود يقبل ────────────────────────► [PROVIDER_ACCEPTED / AWAITING_PAYMENT]
                                                    │
                                                    ├─── انقضاء مهلة الدفع ──► [PAYMENT_EXPIRED] (صفر دفع)
                                                    │
                                                    └─── العميل يسدد ────────► [PAYMENT_PROCESSING]
                                                                                  │
                                                                                  ▼ (Webhook تأكيد موثق)
                                                                             [CONFIRMED]
                                                                                  │
                                                                                  ▼ (يوم المناسبة)
                                                                             [IN_EXECUTION]
                                                                                  │
                                                                                  ▼ (انتهاء المناسبة)
                                                                             [COMPLETED]
                                                                                  │
                                                                                  ▼ (انتهاء فترة النزاع)
                                                                             [SETTLED]
```

#### تعريف الحالات:
1. **`REQUESTED` / `AWAITING_PROVIDER_DECISION`:** تم تقديم الطلب من العميل ويخضع لمراجعة المزود.
2. **`PROVIDER_ACCEPTED` / `AWAITING_PAYMENT`:** تمت موافقة المزود وصدر عرض السداد النهائي مع مهلة سداد محددة (`paymentDeadline`).
3. **`PAYMENT_PROCESSING`:** تجري معالجة السداد عبر بوابة الدفع الإلكترونية.
4. **`CONFIRMED`:** تم التحقق من السداد وتأكيد الحجز رسمياً وإصدار الفاتورة الضريبية وتوزيع مبالغ الضمان المعلق (`Escrow`).
5. **`REJECTED`:** تم رفض الطلب من قبل المزود (لا تتولد أي حركة مالية).
6. **`EXPIRED` / `PAYMENT_EXPIRED`:** انتهت مهلة رد المزود أو مهلة سداد العميل (لا تتولد أي حركة مالية).
7. **`COMPLETED`:** اكتملت المناسبة بنجاح.
8. **`CANCELLED`:** تم إلغاء الحجز المؤكد وفق سياسة الإلغاء والاسترداد المعتمدة.

### 5. الثوابت الرياضية والمحاسبية الحاكمة (Financial Axioms)

```
                            ┌────────────────────────┐
                            │   Accepted  ≠  Paid    │
                            └────────────────────────┘
                                        ▲
                                        │
           ┌────────────────────────────┴────────────────────────────┐
           │                                                         │
┌──────────────────────────────────────┐  ┌──────────────────────────────────────┐
│  القبول يفتح نافذة السداد المؤقتة    │  │  لا يتم إنشاء قيد في دفتر الأستاذ    │
│  ولا يمثل أي تحصيل مالي نهائي        │  │  ولا يتم حجز أموال إلا بعد السداد    │
└──────────────────────────────────────┘  └──────────────────────────────────────┘
```

$$ \text{Confirmed Booking} = \text{Provider Acceptance} + \text{Verified Payment Event} $$

### 6. الشمولية للقاعات والخدمات المساندة (Universal Application)
تُطبق نفس القواعد بدقة متماثلة على:
1. **حجوزات القاعات والأماكن (Venue Bookings).**
2. **طلبات الخدمات المساندة المستقلة (Independent Services: تصوير، ضيافة، إضاءة، كوش وتنسيق، إلخ).**
3. **الخدمات المضافة لمتجر القاعة (In-Venue Addons).**
