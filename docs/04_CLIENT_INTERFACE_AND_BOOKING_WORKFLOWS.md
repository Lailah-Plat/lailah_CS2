# 🛒 وثيقة واجهة العميل وتدفقات حجز القاعات والخدمات
**Client Interface Experience, Hybrid Pricing Model & End-to-End Booking Workflows**

---

## 1. واجهة العميل وتجربة الاستكشاف (Client Interface & Search Engine)

توفر واجهة العميل في منصة **ليلة** تجربة استكشاف عصرية ومرنة تتيح للمستخدمين التنقل بين القاعات والأماكن والخدمات المساندة للفعاليات بنقرة واحدة.

### 1.1 مكونات واجهة العميل الرئيسية
1. **شريط البحث والتصفية المتطور:**
   - الفلترة حسب المدينة والحي.
   - الفلترة حسب السعة الاستيعابية والنطاق السعري.
   - الفلترة حسب المميزات والتجهيزات (إضاءة، مسرح، شاشات عرض، مواقف، إلخ).
2. **استعراض الوسائط العريضة:**
   - معرض صور عالي الدقة يلتزم بأسلوب العرض الشاشاتي (16:9).
   - المشغل المدمج لمقاطع الفيديو التوضيحية للقاعة (`MP4`).
3. **عرض بيانات المزود بحسب إعدادات الخصوصية:**
   - يظهر اسم المزود التجاري أو الاسم المستعار بناءً على حقل `showProviderToCustomers`.

## 2. قواعد نموذج التسعير الهجين وحظر الازدواجية (Hybrid Pricing & De-duplication Rules)

تلتزم واجهة الحجز بنموذج التسعير الهجين الذكي الذي يحمي أسبقية وأولوية مزود القاعة الأصلي ويمنع التعارض التشغيلي:

```
                           [بداية خطوات حجز القاعة]
                                     │
                                     ▼
                   ┌───────────────────────────────────┐
                   │  فحص الخدمات المضافة التابعة للقاعة │
                   └─────────────────┬─────────────────┘
                                     │
           ┌─────────────────────────┴─────────────────────────┐
           ▼                                                   ▼
┌──────────────────────────────────────┐            ┌──────────────────────────────────────┐
│  في حال توفر خدمات مضافة مدمجة بالقاعة│            │  في حال عدم توفر فئة خدمة معينة       │
│  • عرض خدمات القاعة الداخلية أولاً   │            │  • فتح خيار إضافة مزود مستقل خارجي   │
│  • حظر اقتراح مزودين مستقلين بدلاء    │            │  • الحفاظ على أولوية خدمات القاعة    │
└──────────────────────────────────────┘            └──────────────────────────────────────┘
```

### 2.1 ضوابط نموذج التسعير الهجين
1. **أولوية الخدمات الداخلية للقاعة:** إذا كان مزود القاعة المحددة يقدم خدمة إضافية مدمجة تنتمي لفئة معينة (مثل: الضيافة، التوثيق والتصوير، الصوتيات)، يُلزم النظام الواجهة بإظهار تلك الخدمات الخاصة بالقاعة فقط ضمن خطوة الخدمات المضافة.
2. **حظر تداخل الخدمات الخارجية المستقلة:** يُحظر برمجة أي اقتراح لمزودي خدمات مستقلين من نفس الفئات المتاحة مسبقاً لدى القاعة لمنع تضارب المواعيد والتعارض التشغيلي أثناء الفعالية.

## 3. خط الاستكشاف والطلب والحجز والتحصيل الشامل (End-to-End Booking & Approval Lifecycle)

### 3.1 الأصل الحاكم لمنظومة الحجز والخدمات المساندة
**"لا تنشأ أي عملية دفع للحجز أو طلب الخدمة قبل موافقة المزود واعتماده للطلب."**

```
إنشاء المناسبة / اختيار القاعة والخدمات والإضافات
                      │
                      ▼
        إنشاء طلب الحجز أو طلب الخدمة
                      │
                      ▼
   تثبيت تفاصيل الطلب والسعر المبدئي المتوقع
       (Pre-Approval Commercial Snapshot)
                      │
                      ▼
              انتظار قرار المزود
         (Awaiting Provider Decision)
                      │
   ┌──────────────────┼──────────────────┐
   ▼                  ▼                  ▼
[ رفض الطلب ]      [ انتهاء المهلة ]    [ قبول المزود ]
(REJECTED)         (EXPIRED)          (PROVIDER_ACCEPTED)
   │                  │                  │
   ▼                  ▼                  ▼
إغلاق الطلب        انتهاء الطلب      تثبيت Payment Quote النهائي
   │                  │             وفتح مسار الدفع بمهلة محددة
   ▼                  ▼             (AWAITING_PAYMENT & Deadline)
 ┌──────────────────────┐                │

                                         │

                                     (CONFIRMED)

                                         ▼
                                      التنفيذ
                                         │
                                         ▼
                                      الإكمال
                                         │
                                         ▼
                               فترة الاستحقاق / النزاع
                                         │
                                         ▼

                                         │
```

### 3.2 مخطط التفاعل التتابعي بين الأطراف (Sequence Diagram)

```
[العميل Customer]           [واجهة منصة ليلة]           [خادم المعالجة API]           [المزود Provider]           [بوابة الدفع Gateway]
       │                            │                            │                            │                            │
 1. إنشاء الطلب ───────────────────►│                            │                            │                            │
       │                            │ ─── إرسال طلب الحجز ──────►│                            │                            │
       │                            │ (Pre-Approval Snapshot)    │ ─── إشعار طلب وارد ───────►│                            │
       │                            │                            │                            │                            │
 2. انتظار القرار ◄─────────────────┼ ─── Awaiting Decision ─────┤                            │                            │
       │                            │                            │                            │                            │
 3. قرار المزود                     │                            │ ◄─── اعتماد وقبول الطلب ───┤                            │
       │                            │                            │ (Provider Acceptance)      │                            │
       │                            │                            │                            │                            │
 4. فتح مسار السداد ◄───────────────┼ ─── Final Payment Quote ───┤                            │                            │
    (Payment Deadline)              │                            │                            │                            │
       │                            │                            │                            │                            │
 5. سداد العميل ───────────────────►│ ─── بدء الدفع المعتمد ────►│ ─── إنشاء نية دفع ─────────────────────────────────────►│
       │                            │                            │                            │                            │ ─── التحقق والتأكيد ───┐
       │                            │                            │ ◄─── Webhook Verified Payment ──────────────────────────┴─────────────────┘
       │                            │ ◄─── CONFIRMED ────────────┤ ─── إشعار التأكيد النهائي ─►│
 6. استلام سند الحجز والفاتورة ◄────┘                            │ (BKG-26-XXXX & INV-26XXXX) │
```

### 3.3 تفصيل مراحل الدورة التشغيلية والمالية:
1. **مرحلة التحديد والطلب المبدئي (Request Stage):**
   - اختيار القاعة، الفترة، الخدمات المضافة، أو الخدمة المساندة المستقلة.
   - تثبيت تفاصيل الطلب والشروط في **Pre-Approval Commercial Snapshot**.
   - إعطاء الطلب حالة `REQUESTED` أو `AWAITING_PROVIDER_DECISION`.
2. **مرحلة مراجعة وقرار المزود (Provider Review):**
   - **في حال الرفض (`REJECTED`):** إغلاق الطلب فوراً دون إنشاء أي معاملة دفع، بدون رسوم بوابة، وبدون أي قيود استرداد.
   - **في حال انتهاء المهلة (`EXPIRED`):** انتهاء صلاحية الطلب وإلغاؤه وتحرير التواريخ تلقائياً دون أي دفع أو استرداد.
   - **في حال القبول (`PROVIDER_ACCEPTED`):** تحويل الطلب إلى `AWAITING_PAYMENT` وتثبيت **Final Payable Snapshot / Payment Quote** مع تحديد مهلة دفع زمنية ملزمة (**Payment Deadline**).
3. **مرحلة السداد والتأكيد المالي (Payment & Confirmation):**
   - إذا سدد العميل في المهلة: إصدار `Verified Payment` ➔ ترقية الطلب إلى `CONFIRMED` ➔ توليد رقم الحجز `BKG-YY-XXXXXXXXXX` والفاتورة الضريبية `INV-YYXXXXXXXXXX` ➔ توزيع الحصص في الضمان المعلق (`Escrow`).
   - إذا انقضت المهلة دون سداد: تحول الطلب إلى `PAYMENT_EXPIRED` وتحرير المواعيد فوراً دون الحاجة لأي Refund.
4. **الثابت المالي الأهم:**
   - **`Accepted ≠ Paid`** (القبول يتيح الدفع ولا يعني إتمام السداد).
   - **`Accepted + Verified Payment = Confirmed Booking / Confirmed Service Order`**.

## 4. نظام التعليقات والتقييمات المعتمدة (Ratings & Reviews Module)
1. **التقييم المشروط بالحجز:** يُسمح فقط للعملاء الذين أكملوا حجزاً أو طلب خدمة مؤكداً بإضافة تقييم ومراجعة.
2. **عناصر التقييم:**
   - التقييم النجمي الشامل (من 1 إلى 5 نجوم).
   - تقييم النظافة، جودة الخدمة، والالتزام بالمواعيد.
   - كتابة التعليق والملاحظات النصية.
3. **مراجعة الإدارة:** تظهر التقييمات في لوحة تحكم الإدارة لمتابعة مؤشرات جودة الخدمات والموافقة عليها.
